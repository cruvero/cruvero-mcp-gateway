# Phase 17B: SonarQube Integration

## Overview

Create a `sonar-project.properties` configuration file for SonarQube analysis and optionally add a SonarQube scanner step to the CI workflow.

## Scope

### SonarQube Project Configuration (`sonar-project.properties`)

Create the configuration file at the repository root:

```properties
sonar.projectKey=cruvero_mcp-gateway
sonar.projectName=cruvero-mcp-gateway
sonar.organization=cruvero

sonar.sources=cmd,internal
sonar.tests=internal
sonar.test.inclusions=**/*_test.go
sonar.go.coverage.reportPaths=coverage.out
sonar.go.tests.reportPaths=test-report.json

sonar.exclusions=**/testdata/**,**/vendor/**,docs/**,charts/**,deploy/**,scripts/**,migrations/**
sonar.coverage.exclusions=**/testutil/**,**/*_test.go,cmd/mcpgw/main.go

sonar.qualitygate.wait=true
```

**Key paths:**
- Sources: `cmd` and `internal` directories (all Go source)
- Tests: `internal` (test files are colocated)
- Coverage report: `coverage.out` (generated by `go test -coverprofile`)
- Test report: `test-report.json` (generated by `gotestsum` or `go test -json`)
- Exclusions: testdata, vendor, docs, charts, deploy, scripts, migrations

### Optional CI Step (`.github/workflows/ci.yml`)

Add a SonarQube scanner step to the CI workflow. This step should:

- Run after the test and coverage jobs complete
- Use `SonarSource/sonarqube-scan-action@v5`
- Pass `SONAR_TOKEN` from repository secrets
- Generate coverage profile first: `go test -coverprofile=coverage.out ./...`
- Gate: `sonar.qualitygate.wait=true` blocks the step until analysis completes

**Note:** This step is optional and can be enabled by uncommenting or by adding a repository secret. It should not break CI when the secret is not configured.

### Coverage Report Generation

The CI workflow's `coverage` job already runs `./scripts/check-coverage.sh`. For SonarQube, an additional step generates the combined coverage profile:

```bash
go test -coverprofile=coverage.out -covermode=atomic ./...
```

This can be added to the existing `coverage` job or to a new `sonar` job.

## Files Created or Modified

| File | Description |
|------|-------------|
| `sonar-project.properties` | New SonarQube project configuration |
| `.github/workflows/ci.yml` | Optional SonarQube scanner step (can be commented out) |

## Testing Requirements

- `sonar-project.properties` file exists and has valid property syntax
- Source and test paths match actual repository structure
- Coverage exclusion patterns correctly exclude test utilities and test files
- CI workflow remains valid YAML after adding the optional step
- SonarQube step does not fail CI when `SONAR_TOKEN` secret is not set
